Visitor loads index.html — check localStorage for cached weather

3a
Row exists + under 3 hours old → return cached row, skip OWM call
3b
Row exists + over 3 hours old → fetch fresh weather from OpenWeatherMap, PATCH weather fields only (score never changes here)
3c
No row yet → fetch OWM, run scoring algorithm, INSERT full row into Supabase
Score is set once here and never touched by refresh again
4
After returning the row: if past 8AM NYC and no synopsis_approved exists, auto-generate synopsis via Claude Haiku and save it
5
Client renders: score, headline, penalty pills, outfit tags, 5-day forecast, synopsis
Supabase score always wins over client-side score. Synopsis only shows if approved = true.
6
track-visit fires in background — logs the visit for analytics, no UI impact

Score Rules
Set once — score is calculated and saved when the daily row is first created. Never recalculated by a refresh.
Force Refresh — updates all weather data (temp, high, rain, etc.) from OWM but does not touch the score.
Score Override — the only way to change the score after row creation. Admin panel → weather section → type a number and click Set Score. Writes directly to Supabase.
Client vs server — both pages run scoreWeather() client-side as a fallback, but weather.score from Supabase always wins if it exists.
Synopsis System
Auto-Generation (server-side)
Triggers inside get-daily.js after returning the row — if past 8AM NYC and no synopsis_approved on today's row
Pulls up to 8 writing examples from Supabase: curated synopsis_examples anchor first, then recent approved daily rows fill remaining slots
Uses system/user prompt split — CNW voice guide in system prompt, weather data + examples in user prompt
Voice formula: [weather overview] — [action or cultural reaction]. Em dash as hinge. Lowercase-casual, NYC direct, no filler, no hashtags.
Hard cap: 140 characters enforced in prompt AND server-side trim at last sentence boundary
Saves result directly to synopsis_approved + sets approved = true — live immediately
Manual (Admin Panel)
Click ↻ Regenerate → calls generate-synopsis.js (same Claude logic) → lands in textarea as a draft, not yet live
Click ✓ Approve & Publish → calls approve-synopsis.js → PATCHes Supabase → live to all visitors immediately
Editing the textarea after approving shows ↑ Override & Publish — you have to re-approve to push the edit live
States
not generated
No draft or approved text. Click Regenerate.
draft — not yet published
AI wrote it, not approved. Visitors see "today's vibe dropping soon."
edited — not yet published
You edited the textarea after approval. Hit Override & Publish to go live.
approved & live
In Supabase, visible to all visitors. Source of truth.
Caching
Client cache — stored in localStorage under key cnw_weather. TTL: 30 minutes. Busted if date changes, version mismatch, or TTL expired.
Cache version — currently v4. Must match in both index.html and admin.html. Bump both to force all devices to re-fetch.
Server cache — Supabase row is the cache. Stale threshold: 3 hours. Exceeded → fresh OWM fetch + PATCH to Supabase.
Force Refresh (admin only) — bypasses 3hr threshold, fetches OWM immediately, writes to Supabase, busts local client cache.

IG Automation
auto-post-ig.js · cron 8:00 AM EDT
Pipeline
1
Cron fires — Netlify scheduled function at 0 12 * * * UTC = 8:00 AM EDT (summer). Change to 0 13 * * * in winter (EST).
Also triggerable manually: POST to /.netlify/functions/auto-post-ig with { "password": "..." }
2
Check ig_posted — fetch today's Supabase row. If ig_posted = true, exit immediately (no graphic rendered).
Guard fires before any expensive work to avoid wasted renders on re-runs.
3
Generate graphic — if no story_image_url on the row, calls generateAndUpload(). Monday → weekly template, all other days → daily template.
Uploads feed (1080×1350) and story (1080×1920) PNGs to Supabase storage. Saves URLs to daily row.
4
Generate caption — Claude Haiku writes 2–3 line caption with score, vibe, and hashtags. If Anthropic fails, a fallback caption is used so the post still goes out.
5
Create Meta containers — POST to /{ig_user_id}/media for feed (4:5, with caption) and story (9:16, no caption) in parallel.
6
Wait for FINISHED — poll /{container_id}?fields=status_code every 3 seconds, up to 90 seconds per container. Throws if status = ERROR or timeout.
This step is required — publishing before FINISHED returns "MEDIA ID IS NOT AVAILABLE" error.
7
Publish — POST to /{ig_user_id}/media_publish for feed and story in parallel.
8
Record in Supabase — PATCH daily row: ig_posted = true, ig_post_id, ig_caption, ig_posted_at.
Notes & Gotchas
Token expiry — META_PAGE_ACCESS_TOKEN expires every ~60 days. Replace with a never-expiring system user token before Aug 2026.
If posting fails — ig_posted stays false. Re-run manually from admin panel; if the graphic was already generated it won't re-render, just re-posts.
Safe to deploy without Meta creds — if META_IG_USER_ID or META_PAGE_ACCESS_TOKEN env vars are missing, the function exits with skipped: true and no error.
Env vars needed: META_IG_USER_ID META_PAGE_ACCESS_TOKEN ANTHROPIC_KEY SUPABASE_URL SUPABASE_SERVICE_KEY ADMIN_PW

Weather Alert System
two-layer detection + automated IG post
Layer 1 — Daily Flag (get-daily.js)
detectAlert(weather) runs on every row insert and 3-hour refresh
Stores result in alert_flag column of the daily table
TypeCondition
hotDaily high ≥ 95°F or feels like ≥ 100°F
coldDaily high ≤ 28°F or feels like ≤ 20°F
stormPrecip ≥ 70% AND (thunderstorm condition OR wind ≥ 25 mph)
Layer 2 — Forecast Lookahead (check-forecast.js)
Runs 7AM daily. Fetches OWM 5-day/3-hour forecast and groups slots by NYC date.
Detects single-day extremes: high ≥ 95°F / feelsLike ≥ 100°F, high ≤ 20°F, major storm
Detects multi-day patterns: heat wave (3+ consecutive days ≥ 90°F), cold snap (3+ consecutive days ≤ 32°F)
Multi-day patterns deduplicate individual alerts covered within the same date range (coveredDates Set)
Results stored in forecast_alerts table. Admin panel shows upcoming events with one-click "→ Post Alert" buttons.
Auto-Post Pipeline (auto-post-alert.js)
1
Noon cron fires — fetch today's daily row, check alert_flag. If null, skip.
2
Duplicate guard — if alert_ig_posted = true, skip. Optimistic lock sets it to true before generating to block concurrent runs.
3
Generate copy — two parallel Haiku calls: advisory (2 punchy lines for the card) + caption (2–3 lines + hashtags for IG). Both in CNW voice.
4
Render + upload — drawAlertCard(type, temp, advisory) from trigger-alert.js. PNG uploaded to Supabase storage.
5
Post to IG — Meta Graph API container → poll → publish. Writes alert_ig_post_id + alert_ig_caption back to daily row.
Admin Panel
Red banner at top of admin when today's row has alert_flag set — one-click "→ POST ALERT" pre-fills the trigger form
Upcoming Alerts panel (between 5-Day Outlook and Site Analytics) shows forecast_alerts events with per-event "→ Post Alert" buttons

Supabase Tables
daily
One row per day. Key: date_key (NYC date, YYYY-MM-DD)
Weather fields: temp high low feels_like condition humidity precip_chance wind_speed forecast (JSON)
Score fields: score penalties (array)
Synopsis fields: synopsis_draft synopsis_approved approved (bool)
Image fields: feed_image_url (1080×1350 4:5 PNG) · story_image_url (1080×1920 9:16 PNG). Set by generateAndUpload(), persisted so the cron re-uses them without re-rendering.
IG fields: ig_posted (bool) · ig_post_id · ig_caption · ig_posted_at
Alert fields: alert_flag ('hot' | 'cold' | 'storm' | null) · alert_ig_posted (bool) · alert_ig_post_id · alert_ig_caption
Meta: updated_at
synopsis_examples
12 curated hand-picked voice anchor examples. Fields: synopsis temp feels_like condition precip_chance score created_at
These anchor the Claude prompt first — curated examples load before recent daily rows to keep voice locked. Recent approved rows fill remaining slots up to 8 total.
forecast_alerts
Written daily at 7AM by check-forecast.js. Fields: id run_at alerts (JSONB array of upcoming alert objects)
Each alert object: type (extreme_heat / extreme_cold / heat_wave / cold_snap / major_storm) · date or startDate/endDate · maxHigh / minHigh / days
Multi-day patterns (heat wave, cold snap) deduplicate any single-day alerts covered within the same date range.
page_views
Written on every page load by track-visit.js. Fields: date_key (NYC YYYY-MM-DD) · visitor_id (localStorage UUID) · session_id (sessionStorage UUID) · referrer
RLS on this table blocks anon key reads. get-analytics.js uses SUPABASE_SERVICE_KEY to bypass RLS. Writes via track-visit.js also use service key.
subscribers
Phone numbers for SMS beta. Fields: phone created_at active (bool)
